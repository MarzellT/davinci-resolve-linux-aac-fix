# Native AAC compatibility port for Resolve Studio 21.1.0.17

**AI disclosure:** This port, its documentation, tests, and accompanying PR were
fully generated by OpenAI Codex. Automated checks and Resolve integration tests
were run on the contributor's machine; they are not a substitute for maintainer
review. No independent human code review is claimed.

**Experimental, integration tested on this exact build.** The old upstream
`install.sh` does not install this port. Use the native-specific scripts below.
Resolve upgrades require a new version-specific review; this port refuses them.

Supported executable SHA-256:
`99d4e0a46d63cbfe71ce4b30f23c5654ffbdd17d782d9368986cecd159e415d0`

The port is `src/aac_native_21.c` + `src/aac_native_21.S`. It is separate from
upstream `aac_hybrid_shim.c` and deliberately has no file-open interposition,
transcoding, sibling media, metadata removal, or FFmpeg subprocess. It connects Resolve's existing MP4 reader to an ABI-matched supplemental AAC
decoder because this installation's bundled AAC decoder is absent.
It neither modifies `/opt/resolve/bin/resolve` nor media files.

## Why this is not just updating seven offsets

The codec dispatch uses different registers and control flow in 21.1. Its
FFmpeg codec map contains ALAC, FLAC, MP3 and AC3; there is no disabled AAC map
entry to rename. The upstream apparent extradata-validity checks actually
compare the codec ID to ALAC (`0x15010`); replacing them with AAC would change
ALAC behavior. The upstream fixed ESDS offset plus vector-start-pointer change
also risks wrong offsets and incorrect deallocation for compact descriptors.

Four AAC-specific detours preserve the existing non-AAC branches:

1. At the unsupported-format branch in the reader's dispatch, recognize AAC
   and use the same wrapper as MP3/FLAC. Existing NONE/PCM behavior is preserved.
2. At the wrapper's codec-map lookup, provide a synthetic read-only AAC entry
   for AAC only. The actual map remains unchanged.
3. Include AAC in the path that asks the reader for codec extradata, preserving
   both original ALAC and FLAC cases.
4. Copy AAC's ESDS bytes to libavcodec without running the ALAC header rewrite.

At that exact wrapper's `avcodec_open2` call, a bounded ISO descriptor parser
extracts AudioSpecificConfig. It accepts expandable descriptor length fields
of 1–4 bytes and optional ES headers. It moves ASC within the already allocated
libavcodec-owned buffer and updates its size; the C++ vector and its allocation
start/end remain untouched. This avoids upstream's fixed `+0x1f` assumption.
Calls from other code paths are unaffected.

## Guards and memory protections

Only the actual `/opt/resolve/bin/resolve` executable is targeted (never fuscript,
FFmpeg, Python, or other subprocesses). Its full SHA256 and every complete
instruction fingerprint are checked before any executable memory is changed.
Unknown versions are left unmodified. Original pages must be RX and owned by
that executable; the private trampoline allocation transitions RW→RX. All
patch pages are obtained before writing and restored to their original RX
permissions. Permission restoration failures terminate startup rather than
allow a partially changed runtime. No writable executable mapping is created.

## Build and initial parser checks

```
gcc -shared -fPIC -O2 -Wall -Wextra -Werror -Wno-deprecated-declarations \
  -o aac_native_21.so src/aac_native_21.c src/aac_native_21.S -ldl -lcrypto -pthread
```

Dependencies: Linux x86_64, GCC/binutils, OpenSSL development headers/library.
Resolve's bundled codecs remain in use for existing formats. A minimal FFmpeg
6.0 AAC-only library is loaded locally for AAC; no system FFmpeg decoder or
global library override is used.

`tools/test-native-parser.c` passed AddressSanitizer and UndefinedBehaviorSanitizer
checks for the exact original Nano ESDS, compact-length ESDS, every truncated
Nano ESDS length, and 200,000 malformed/mutated inputs. These parser tests are
necessary but not sufficient for proving host compatibility.

Required integration tests: native AAC stereo and mono playback/waveforms and
PCM render vs independent FFmpeg decode, the original Nano descriptor, existing
PCM/FLAC/ALAC regressions, media/binary hashes unchanged, and no transcoded files.

## Additional 21.1 blocker found by the debugger

The four detours reached the AAC wrapper correctly, but Resolve's bundled
`libavcodec.so.60.3.100` returned NULL for `avcodec_find_decoder(AV_CODEC_ID_AAC)`.
Its MP3/FLAC decoders exist; its AAC decoder is actually absent. Consequently
routing changes alone still render silence on this installation. This differs
from the upstream patch's assumption about Resolve 20.3.2.

The experimental bridge accepts `RESOLVE_AAC_DECODER_LIBRARY` pointing to a
minimal shared FFmpeg 6.0 codec library (exact ABI version 60.3.100) built with
only the AAC decoder enabled. It loads this separately and locally, without
replacing any `/opt/resolve` library or changing global library search paths.
AAC contexts created by the bridge are registered under a mutex; their
open/send/receive/flush/close/free operations go to that decoder. All other
contexts continue through Resolve's bundled library. The shared libavutil58
frame/buffer ABI avoids mixing unrelated frame layouts and allocators.

The library
path is mandatory when Resolve has no AAC decoder; absent/mismatched backends
cause startup to leave the executable unpatched.

## Integration results (2026-09-25)

- Unpatched AAC render: all 768,000 stereo samples were zero.
- Patched native stereo AAC, mono AAC, exact original Nano ESDS, and compact
  one-byte-length ESDS: rendered real audio at the original sample alignment.
- Existing PCM, FLAC and ALAC: regression exports still decoded correctly.
- Interior exported samples correlated approximately 1.0 with independently
  decoded reference audio, maximum error 5.96e-8 and zero sample lag. Resolve's
  boundary fades account for small whole-file differences.
- A direct backend test decoded 385,024 AAC samples with peak 0.217295676 using
  Resolve's original packet/frame allocators plus the supplemental codec, then
  freed packets, frames and context successfully.
- Process maps verified both codec libraries but only the original bundled
  libavutil58, preserving frame/buffer ownership compatibility.
- The real constructor was tested against an intentionally unsupported hash:
  it returned before backend loading or memory patching (`tools/test-version-guard.c`).
- The locally tested bridge build had
  SHA256 `c370310a8b6bcb3933263cbfb3bee6969c2342b0e65f0a607cce9a3de47de02a`.

A short render from a real DJI Osmo Nano recording also passed:
its reconstructed input matched the original source SHA256 exactly, native AAC
render contained sound, both channels had correlation 0.9999017 and zero sample
lag against the independent reference. The Resolve executable remained unchanged
at SHA256 `99d4e0a46d63cbfe71ce4b30f23c5654ffbdd17d782d9368986cecd159e415d0`.

**Coverage limits:** AAC-LC in MP4 is tested, including mono/stereo and normal/
compact descriptor lengths. HE-AAC/SBR, AAC surround, encrypted media, and other
containers have not been validated. Do not infer their support from libavcodec's
feature list. This is a decoding fix only, not AAC encoding/export support.

## Use and rollback

`tools/install-native.sh` installs a **separate** application entry named
**DaVinci Resolve (Native AAC)**. It leaves the ordinary Resolve launcher and
all `/opt/resolve` files untouched. Close Resolve, then launch that entry to
activate native AAC decoding for that process. Media already converted to PCM
continues to work. This is a decoding fix; it does not add AAC export support.

The launcher verifies the exact executable hash and both packaged library hashes.
On a different Resolve version it refuses to start the modified process and
asks you to use the ordinary launcher. Do not remove this guard or copy offsets
from another Resolve version.

To turn the feature off, close Resolve and use its ordinary launcher. To remove
its files and desktop entry, run `tools/uninstall-native.sh`. Neither operation
changes footage, media cache files, or project databases. A project imported
with working AAC may need its old silent waveform cache regenerated if reused
from an earlier failed import.

## Reproducible build

1. `tools/build-native-decoder.sh [build-directory]` downloads the pinned official
   FFmpeg 6.0 source archive and verifies SHA256 before building only AAC. It
   disables inline assembly to avoid modern-binutils failures in FFmpeg 6.0.
   This needs curl, tar, GCC, make and patchelf.
2. `tools/package-native.sh [decoder-prefix]` builds the shim and stages the
   decoder, licenses and checksum manifest in `native-package/`.
3. Run `tools/test-native.sh` for parser/version-guard checks. Follow the
   integration protocol below before trusting a new build.
4. `tools/install-native.sh` installs the staged package in
   `~/.local/share/resolve-native-aac` and its separate desktop entry.

The supplemental FFmpeg library is LGPLv2.1; its license is included. Its source
archive hash is `57be87c22d9b49c112b6d24bc67d42508660e6b718b3db89c44e47e289137082`.
The source and complete configure/build logs are retained in
`~/.local/state/resolve-aac-port-build`. This is an unofficial local interoperability
port, not a Blackmagic-supported change.

## Re-running the checks

```bash
bash tools/test-native.sh
ffmpeg -f lavfi -i 'sine=frequency=440:sample_rate=48000:duration=8' \
  -ac 2 -af volume=2 -c:a aac -b:a 192k -f adts /tmp/native-aac-test.aac
python tools/test-supplemental-aac.py \
  "$HOME/.local/state/resolve-aac-port-build/decoder/lib/libavcodec.so.60.3.100" \
  /tmp/native-aac-test.aac
```

The decoder smoke test uses the installed Resolve libraries and checks decoding
and allocation ownership; the sanitizer tests do not launch Resolve. The decoder
test needs Python 3 and an eight-second stereo 48 kHz AAC-LC ADTS input with a
peak above 0.1. The fixture command above supplies one.

For an end-to-end check, use a separate Resolve project with no linked proxies
or effects. Import a known AAC MP4 and export a short MOV with PCM audio, first
through the normal launcher, then through the Native AAC launcher. Verify sound,
channel count, waveform generation, duration and sample alignment against an
independent FFmpeg decode. Repeat for mono AAC, camera-native and compact ESDS,
and PCM/FLAC/ALAC inputs. Check that media and executable hashes are unchanged.
Use a render destination inside Resolve's configured media storage.

The recorded results above cover exported audio and decoder operation. Visual
waveform/playback confirmation remains a separate check for maintainers; do not
treat the existence of a waveform alone as evidence that final rendering works.
